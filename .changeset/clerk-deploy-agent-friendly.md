"clerk": minor

Let AI agents take a Clerk application to production.

- `clerk deploy --domain <domain>` in agent mode creates the production instance (or resumes the existing one) without prompting and prints the deploy report. Without `--domain` it stays read-only. In the wizard, `--domain` skips the domain prompt and `--yes` skips the confirmations.
- `clerk deploy --domain` refuses a domain it can't apply: with an existing production instance on another domain it fails with `production_instance_exists`, and while Clerk hasn't returned the existing instance's domain yet it fails with the new `deploy_domain_unchecked`, in agent mode and the wizard alike.
- A 404 on the production domain's status, in `clerk deploy`, `clerk deploy status`, or the wizard's DNS polling, now fails with `deploy_instance_unresolved` instead of `not_linked` and its advice to re-link the directory.
- The deploy report gains `oauth.setup`: for each provider missing production credentials, the redirect URI, authorized origins, fields, and the `clerk config patch` payload and command that save them. `nextAction` now names the command to run instead of handing off to a human terminal, except for Apple's private key and, when the app uses native-only Sign in with Apple, Apple web credentials, which still go through `clerk deploy` in a terminal. OAuth secrets go into a file outside the project that the user fills in and that is removed afterwards. When native-only Sign in with Apple isn't ready in production, Apple is left out of `oauth.setup` so the native fix in `nextAction` isn't buried. Once Clerk's side is complete, `nextAction` says to pipe the production keys into the host's CLI without reading them.
- `clerk env pull --print` prints `KEY=value` lines to stdout instead of writing an env file, for sending production keys to a hosting provider. It fails without printing anything when Clerk returns no secret key. For an unclaimed accountless app, whose keys exist only on this machine, it prints the secret key alone, with a warning, when no publishable key is found locally.
- `clerk config patch` and `clerk config put` print `[REDACTED]` in place of the value of any key whose name contains `secret` or `private_key` (in any case), in the diff they show before writing and in the response they print after (dry runs included). Values under other keys are printed as before. Error bodies logged under `--verbose` are not redacted.
- `clerk config patch` and `clerk config put` refuse a payload that still holds an `oauth.setup` placeholder (`<client_secret>` under `client_secret`), naming each such field, and `clerk deploy status` no longer counts such a value as a saved credential.
