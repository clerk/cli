`clerk init` and `clerk doctor` set up and check an Xcode Multiplatform App target (one target for iOS and macOS, `SDKROOT = auto`) for both platforms in one run, instead of stopping with "Select an iOS or macOS build context". Each configuration is inspected for iOS and for macOS; platforms Clerk doesn't set up, such as visionOS, are named and left unchanged. Both platforms get the Associated Domain (and Sign in with Apple when enabled), and the Mac build of a sandboxed app gets outgoing network access. One native registration covers both platforms, so init stops with an explanation when they build different Bundle IDs. With a Personal Team, which can't give a Mac app Associated Domains, a shared entitlements file that has them or needs the Clerk domain for iOS is split: iOS keeps it, and macOS gets its own copy (`<Name>-macOS.entitlements`, through `CODE_SIGN_ENTITLEMENTS[sdk=macosx*]`) without Associated Domains, and init and doctor say that passkeys and password AutoFill stay off on Mac.
