Support hosting-provider domains in `clerk deploy`. `*.vercel.app` and `*.replit.app` are supported Clerk production domains — served through a proxy rather than CNAME records — but the deploy prompt refused them outright, alongside a list of suffixes that did not match what the API actually rejects. The prompt now accepts provider domains, and because `POST /v1/platform/applications/{id}/instances` is the one domain-creating endpoint that skips Clerk's domain validation and derives no proxy URL, `clerk deploy` asks the API to derive it via `PATCH /v1/platform/applications/{id}/domain` right after the instance is created. Provider domains then get proxy setup instructions instead of DNS records they cannot carry, and the deploy status surfaces the proxy check — previously ignored, so a provider domain could be reported as fully verified while its Frontend API was unreachable. The prompt still refuses the shared hosting domains the rest of Clerk refuses (`*.netlify.app`, `*.herokuapp.com`, `*.fly.dev`, `*.onrender.com`, `*.web.app`, `*.railway.app`), since that endpoint would otherwise create an instance that can never verify and that the CLI cannot delete. Deploy error mapping now matches the codes and statuses the API really returns: `provider_domain_operation_not_allowed` (403), `home_url_taken` (422), plus `known_hosting_domain` and `proxy_url_required_for_provider_domain`.
